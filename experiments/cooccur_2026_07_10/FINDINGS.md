# FINDINGS.md — 规范 §8 之外的意外发现

> 按沟通规约，只**记录**，不解决。

---

## F1. golden set 的"韩立"覆盖与 DF 剪枝的直接冲突

**现象**: 8 个 golden seed 里有 3 个（李化元、筑基丹、银月）把"韩立"列
为 expected 邻居。但"韩立"是全书最高 DF 词（30.9%），V2/V3 的 DF 自适应
剪枝一定会把它干掉。

**后果**:
- V2 相对 V1 的 P@5 **反而下降**（0.10 → 0.05），并非因为剪枝错了，而是
  golden 认为主角名是有效邻居。
- V3 因为图更稀疏，命中进一步下降到 0.

**逻辑张力**:
- 剪枝角度看："韩立"作为主角名，跟几乎所有其他词共现，是**噪声源**。剪掉是对的。
- 图扩展 QA 角度看：如果用户在检索"李化元"想知道跟他相关的人物，"韩立"
  确实是最相关的（因为他就是主角+对手）。此时"韩立"是**信号**，不是噪声。

**这是一个方法论层面的问题**：DF 剪枝在图扩展任务里可能**过度剪掉高连通
性 hub 节点**。传统 IR 停用词剪枝的直觉不一定适用。

**未解决**（规范作者可能想据此调整 §5 边界或引入 hub-node whitelist 机制）。

## F2. jieba 精确模式对合成词的支持不足，直接影响 seed 命中

**现象**: 8 个 seed 里 4 个（**50%**）在 jieba 精确模式下被切成多个 token：
- "墨大夫" → 墨 / 大夫
- "极阴祖师" → 极阴 / 祖师
- "筑基丹" → 筑基 / 丹
- "大衍神君" → 大衍 / 神君

结果 seed 整词不在词表 → `seed_in_graph=false` → 直接不参与 P@K 平均。

规范 §8 (1) 已经预料到这个，但没预料到会**50%** seed 直接 miss。所有变体
的 seed_coverage 都只有 0.5（V3 因 黄枫谷 边全部被剪，降到 0.375）。

**未解决**（可选方案：给 jieba 添加自定义词典 / 换 pkuseg / 用 substring
索引跳过分词。都超出 tracer bullet 范围）。

## F3. V3 图崩塌：edge 数从百万级到千级

**现象**:
- V0: 2,594,790 edges
- V1: 2,274,259 edges
- V2: 2,012,337 edges
- V3: **8,815 edges** (下降 3 个量级)

主要原因 = min_pair_count=3 + Top-K per line=8 + NPMI>=0.3 三重剪枝叠加。

**影响**:
- unique_terms 从 77k 降到 27k（词表 shrink 65%）
- 黄枫谷 seed 完全掉出图（V1/V2 里都有邻居）

规范 §8 (3) 提到过 PMI 稀疏问题，但 min_pair_count 从 2 提到 3、Top-K 收
紧到 8，这两个改动在小语料上比 NPMI 本身影响更大。

**未解决**（未来若继续做 V4：只调一个变量 / grid search，别再 3 参数一起动）。

## F4. `seed_coverage` 在 V3 与 V2 差异 (0.375 vs 0.500)

黄枫谷在 V0/V1/V2 都有邻居（含"筑基/初期/前辈"），到 V3 邻居列表变空。
V3 的 `seed_in_graph=false` 语义变成"seed 在语料中有 token，但共现关系
全被剪枝剪掉了"，跟 V0/V1/V2 里"seed 根本不在词表"是不同的失败原因。

当前实现两种情况用同一个 `seed_in_graph=false` 表达，规范未区分。
**未解决**（未来若在意可拆成两个字段：`seed_in_vocab` + `seed_has_neighbors`）。

## F5. degradation 边界断言的"strict less"陷阱

规范 §5 说 "mean_p_at_5 都 < 0.1" 触发降级提示。本次实测 V0/V1 恰好等于
0.1，V2=0.05, V3=0.0。按字面严格小于，警告**没触发**，但实际情况其实
就是"全体接近失败"。类似地 pairwise delta 阈值 0.05，V2→V3 恰好 -0.05，
`abs(0.05) < 0.05` 也是 false，警告也没触发。

**边界很脆**。当前实现按规范字面 `< 0.1` 处理。规范作者若想让边界更 robust
可考虑 `<= 0.1` 或增加宽容带（如 `< 0.12`）。**未解决**。
