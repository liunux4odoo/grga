# FINDINGS.md — v2 实验的意外发现（记录即可，不解决）

> 规范 §4 边界维度之外的行为。归档供规范作者参考。

---

## F1. 章节级共现的朴素实现会 OOM（技术发现，已绕过）

**现象**：最初按前作的 `Counter[(a,b)] += 1` 全组合方式做章节级共现，进程被
OOM killer 杀死（exit 137）。

**量化**：全书 2005 章，章节 token set 中位数 564、p90 618、最大 27769。
全组合 pair 事件累计 ≈ **6.94 亿**。在 2GB 可用内存下 Counter 直接撑爆。

**绕过方案**（见 build.py `build_chapter_variant`）：
1. 按 chapter-DF ≥ min_pair_count=3 预筛 term（一个 pair 的章节共现数不可能
   超过任一端 term 的 chapter-DF，所以 DF<3 的 term 不可能进入任何被保留的
   pair）——27429 / 69160 terms 通过
2. 构建 (chapter × term) 二值稀疏矩阵 M（scipy csr，nnz≈1.05M）
3. 分块计算 `M.T @ M`（block=512 term/块），逐块阈值 ≥3 后只留上三角写邻接表

**注意**：这是**纯工程绕过**，不改变共现语义（`M.T@M` 的 (a,b) 项精确等于
"同时含 a 和 b 的章节数"）。规范 §4 只预见了"单章过大 → 截断"，没预见"全局
pair 空间 OOM"——这是章节窗口相比行窗口的一个隐藏放大效应，记录在此。

## F2. 章节窗口让 hub 退化得比 V0 更严重（核心发现，已在 hub_diff.md 详述）

**现象**：V4 韩立 top-30 邻居 = 0 实体，全是虚词/动作/神态词，**比前作 V0
（整行）还差**——V0 top-30 里至少有"修士""道友""老者"这类修仙语域词，
V4 里连这些都被更高频的纯虚词挤出 top-30。

**机制**：主角韩立在 2005 章里几乎章章出现（chapter-DF 极高）。章节窗口下，
`w(韩立, X) = 同时含两者的章节数 ≈ min(DF_韩立, DF_X) ≈ DF_X`（因为 DF_韩立
逼近满值）。于是邻居排序 = 纯 chapter-DF 排序 = 高频虚词排序。**窗口越宽，
hub 的共现权重越接近"另一端词的边际频次"，语义信号被彻底抹平。**

**含义**：这与前作"整行共现在 hub 上退化为频次统计"是同一种退化的**加重版**。
位置约束要救 hub，窗口粒度必须**远小于章节**。

## F3. 新 tokenizer 让前作 4 个 miss 的 seed 全部进图（正向发现）

前作因 jieba 切碎导致 miss 的 4 个 seed（墨大夫/极阴祖师/筑基丹/大衍神君），
加自定义词典后在 V2_retok 里 **4/4 全部进图**（规范 S5 只要求 ≥3）。
`银月` 也因加词典而不再被切成"银/月"。tokenizer 修正按预期生效。

## F4. V2_retok 里韩立仍被 DF-adaptive 剪出图（预期，但值得标注）

V2_retok 沿用前作 V2 的 DF-adaptive（top-30 by DF 动态停用词），韩立 chapter-DF
/ line-DF 最高，被自动剪掉，`seed_in_graph=false`。这是预期行为（前作已记录），
但它意味着**在整行窗口下，"保 hub"和"清污"通过 DF 剪枝无法兼得**：
- 不剪（V0/V1）→ hub 在图但邻居全是噪声
- 剪（V2_retok）→ 邻居干净了但 hub 直接没了

V4 想用位置约束绕开这个两难（不剪 DF 也让邻居干净），但 F2 表明章节粒度做不到。
