# V2_retok top-30 邻居可用性人工审读

> 场景:L2 定位重新为"给 L1 补充遗漏关键字",top-30 输出对 caller 是否够用?
> 判定基准 = "caller 能否用作 L1 补充搜索词"。
>
> 分类:
> - **E (entity)**: 人物/门派/法宝/地名/事件 —— 直接可用
> - **D (domain)**: 修仙语域词(修炼/弟子/洞府/掌门/丹药/前辈/…) —— 可用
> - **F (filler)**: 虚词/程度副词/情态词 —— 不可用
> - **G (gaze/action/body)**: 神态/身体/动作 —— 不可用
>
> **Useful = E + D**。判定尺度取宽(单字量词"一粒/一枚"因语域感强算 D)。

## 关键观察

### 1. 44% 是啥水平?
- Caller 从 top-30 里拿到 **平均 13 个可用词**(≈ 每个 seed 免费扩到 13 个 L1 补充词)
- 门槛判定"≥50% 就够用" → **3/8 达标**(李化元 / 黄枫谷 / 筑基丹)
- 但**零命中率 = 0**:每个 seed 都有 ≥ 1 个 useful 词。方向对。

### 2. 不同 seed 类型表现分层清晰
- **物品/丹药 seed (筑基丹, 67%)**:最好。共现全是"服用/炼制/资质/丹药/灵药"类语域词,配套操作词齐全。E=0 但 D 密度极高。
- **门派/组织 seed (黄枫谷, 57%)**:次好。既给配套语域(掌门/弟子/门派/七派/基期/结丹期)又给相邻实体(令狐/越国/清虚)。
- **配角人物 seed (极阴祖师, 40%; 银月, 43%; 大衍神君, 40%)**:中等。E 密度高(极阴 7 个明确实体!),但也混杂较多虚词。
- **传承性人物 seed (李化元, 50%; 墨大夫, 27%)**:分化严重。李化元邻居全是"师傅/师娘/夫妇/门下"的师承语域,墨大夫邻居里"医术/口诀"直接命中他的身份特征。E 数少但**每个 E 都极其相关**(董萱 = 妻子,余子童 = 同门,七玄门 = 师门)。
- **单字模糊 seed (曲魂, 30%)**:最差。因为"曲魂"两字都是常字,共现被主线剧情稀释。

### 3. Filler + G 类占 55%,是拉低数字的主因
55% 的邻居是"没有/说道/一下/心里/脸上/一眼/露出/看来/竟然"这类词。
LLM 短停用词表(48 词)明显不够。这些词都很规整:
- **程度副词**: 竟然/实在/真的/丝毫/终于/整个/原本
- **情态词**: 应该/可能/不会/不禁/或许
- **量词/指代**: 一下/一个/一位/这位/那位/一句/一番
- **身体/神态**: 脸上/心里/一眼/眼中/脸色/眼神/露出/开口
- **时态词**: 突然/马上/立即/终于/当年/以前

**扩到 200-500 词的常用中文虚词表,可用率能推到 65-75%**。这是纯工程活,不涉及算法。

### 4. Entity 密度的 seed 依赖性

**极阴祖师 top-30 里有 7 个明确实体**(乌丑/天明/天鼎/蛮兄/血玉/玄骨/乌某) —— 这是最大的正向信号。极阴祖师是配角,身边的实体密度高,共现窗口刚好抓到。反过来:
- 墨大夫是**早期短线剧情**人物,只有 3-4 个稳定配角(余子童/张铁/七玄门/长春功)
- 筑基丹是**物品**,身边不该有其他实体
- 曲魂剧情跨度大,配角频繁更换,单个配角共现权重都上不去

**结论**:E 数不该跟 D% 一起看,应该分开看。E ≥ 1 已经是极高价值(caller 靠这 1 个词能跳到 L1 从没索引到的另一批段落)。

## 判定

**44% 的均值 + 零命中率 = 0 + 每个 seed 都有 E 或密集 D** →
**V2_retok 已经够用作 grga 主干集成的起点**,不需要继续调窗口(V5/V6)。

真正该做的是:
1. **扩停用词表**(200-500 词) → 可用率推到 70%+,一次性工程
2. **caller-side filter policy**(告诉 caller "top-30 里挑 E+D,忽略 F+G") → 但这需要 grga 给每个词一个类型标签,难度大
3. **产品化 L2 接口**:输出关键字集合(不是文档),加 hub 告警,加 (seed → useful subset) 的返回结构
4. **对 hub 显式拒绝**:seed 频次过高时返回 `{error: "hub_seed"}`,让 caller 走 L1 或 L3

**不需要**做的:
- 继续 V5/V6 更窄窗口实验 —— V2_retok(整行)已经达标
- 加 PMI / 更复杂剪枝 —— 边际收益不足
- 加 embedding —— 违反 §1 且没必要

## 附:可用率的另一个观察

如果**把标准放宽到"E 数 ≥ 1"这个二值判定**:
- 8/8 seed 都有 ≥ 1 个 useful 词
- 7/8 seed 都有 ≥ 1 个 entity(仅筑基丹例外,但它的 D=20 已经足够代偿)

这个二值判定其实更接近 L2 的产品价值:**caller 不会拿走全部 30 个,他只需要"有 1-2 个 L1 没索引到的相关词"就赢了**。
