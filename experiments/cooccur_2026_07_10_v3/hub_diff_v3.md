## 判定

- 韩立 top-30 by npmi 里 entity 命中数 = **0**，top-100 累计（top-30 + 尾部）= **0**
- **位置约束假设 + npmi ranking 不成立**（在 hub seed 上）

### 数学根因

Spec §4 的假设是：hub npmi 值都可能趋近 0 或负，但**相对排序**应把实体推到前。数据给出的答案是：**相对排序也把实体推到 200+ 之外**。原因：

1. npmi 归一化后，最高分不是「co 高的词」，而是**「co/df_target ≈ 1 的词」**（即「几乎只与 hub 共现」的词）
2. 主角的独占窄词满地都是：韩立的第一人称叙述（韩某）、神态描写（眉梢/微微一笑/不动声色/微眯）、专属动作（摸了摸/递给/一挑）—— 这些词的 df 极小，且几乎每次出现都伴随韩立，`co/df` 逼近 1
3. 关联配角（墨大夫等）与韩立的 `co/df ≈ 0.5-0.6`，虽然绝对 co 高，但 npmi 上被独占叙述词吊打

换句话说：**npmi 找的是「最纯粹的共现」，而 hub 的最纯粹共现是叙述配色，不是剧情实体**。这是 npmi 归一化本身的性质，不是本实验的实现瑕疵。

### 对 L2 caller-first 路线的含义

- **非 hub seed 上 npmi 表现极佳**（top-5 Useful% ≥ 60% 稳过，见 `topk_usability_v3.md`）—— caller-first 假设**在非 hub 上成立**
- **hub seed 上 npmi 不能救**—— top-30 命中 0，说明单一 ranking key 无法同时兼顾 hub 与非 hub
- 契约层面已经保留了 `seed_df` 字段（spec §6.1），caller 可自行拿到 df 决定是否走 hub 分支（例如 df/N > 0.1 时降级为返回「该 seed 是 hub、原始邻居噪声大、建议改问题分解」）
- 若想让 hub 也 work，下轮需要**不同 ranking key**（如 Log Dice、条件概率 P(X|hub)、或子采样后的 pmi），或**caller-side 二次过滤**接口 —— 属 spec §11 fallback 讨论
