## assumption:hanli_df_ratio

**Spec §10 触发条件**：spec 说韩立 df 应"接近 N"。实测 df=46252 / N=139072 =
**0.333**（三分之一）。

处理：**符合 hub 预期，继续实验**（用户已确认）。

- 韩立仍然是**全语料最高频 term**（第二高频 "没有" df=12272，仅韩立的
  1/4，其余更低）。它作为 hub 的地位不动摇。
- 行窗口下，任何单一 term 都不可能真正接近 N —— 每行只有几个 token，即使
  是主角也不会在每一行显式出现（对话/描写/环境行主角不 tokenize 出来）。
  spec §4 用"接近 N"应理解为"df 远高于其他 term"，而不是字面 df≈N。
- 若下版 spec 想收紧此条件，建议改述为"df/N > 0.1 或 df 是次高的 ≥2 倍"。

## assumption:top5_useful_100

**Spec §10 触发条件**：三个 seed（墨大夫、李化元、极阴祖师）的 top-5 Useful
% = **100%**（极端值），要求 double-check 分类。

处理：**分类无误，属 npmi 结构性优势**。理由：

- 墨大夫 top-5 = 余子童(E)/医术(D)/妻室(D)/把脉(D)/妻女(D) —— 全部与"墨
  大夫"这个身份直接绑定的语域词/相关人
- 李化元 top-5 = 仙姑/师娘/夫妇/徒弟/为师 —— 全部师承亲属语域
- 极阴祖师 top-5 = 乌某/蛮兄/乌丑/齐兄/青兄 —— 全部围绕极阴祖师的兄弟辈
  人物变体

这些词的 df 都很小（几个到几十），且**几乎只出现在 seed 附近的段落里**，
npmi 天然把它们顶到前。此现象与 hub seed 上"独占窄词吊打关联实体"是**同
一机制**，只是在非 hub seed 上此机制正好落在语义正确的词上。

不属数据异常，无需调分类规则。

## 实现层记录（不需要 spec 作者答复）

- npmi 公式采用 spec §3 的 Bouma 2009 版：`pmi/-log(co/N)`，值域 [-1, +1]
- log 缓存用 `functools.lru_cache(maxsize=None)` 缓存 `log_df(term)` 和
  `log_co(int)`，实测总耗时 build+report 全流程 27s，远低于 60s 阈值
- 邻接表只对 seed 端存邻居（`adj_co[seed] = {term: co}`），避免 pair
  展开全图（1.2M edges）到 Python dict 造成 10x 内存开销；查询 seed 邻居
  时按需算 npmi
- 排序 tie-break：npmi desc → co desc → term asc（确定性）
