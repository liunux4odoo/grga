## 2. 优先级 backlog

### P0 · 修 `related --mode graph` 的 PPR 塌陷

**WHAT**:同一底层图数据,`related --mode graph <seed>` 返回噪声堆(顶部
是 `.min.js` / 虚词),`graph inspect <seed>` 返回干净共现。差异不是
"哪个通路更好",是**PPR 通路本身有实现层面的病症**。

**证据**:

| 场景 | Seed | `related --mode graph` top-5 | `graph inspect` top-5 |
|---|---|---|---|
| 代码仓库 | `qwenpaw` (低频) | cytoscape.min.js / if / in / is / or | grga / docs / tools / install / caller |
| 凡人语料(V0-V3) | 各类 hub | "的/了/一声/心中/韩立" | (未直接对照,但共现表 raw 数据能出实体) |

**跨场景稳健性矩阵**:

| 判据 | 代码仓库 | 中文小说 | 结论 |
|---|---|---|---|
| PPR 塌陷可复现 | ✅ | ✅ | 跨场景稳健 |
| 底层图数据是否有效 | ✅ (inspect 干净) | ✅ (raw count 有信号) | 数据没问题,通路有问题 |

**病症假设方向**(不预定诊断结果,列几个可能起点):

- edge weight 归一化在 PPR 前是否发生?若否,高 df 邻居天然占优
- 阻尼系数 / 迭代次数是否对稀疏子图不友好?
- Seed vector 构造是否单点集中?低频 seed 会不会因 seed 权重集中在
  1-2 个文档而导致 PPR 收敛到全语料 hub?
- adjacency 是否包含所有低 co_count 边?稀疏化阈值是否过高?

**验收标准**(可执行 shell,跨场景):

```bash
# 场景 1: 代码仓库
grga related "qwenpaw" --mode graph --db-path /tmp/grga_selfscan.db --json \
  | jq '[.neighbors[0:5][].term] | map(select(. as $t | ["if","in","is","or","to","the","and"] | index($t) | not))' \
  | jq 'length >= 3'
# 期望 true (top-5 里至少 3 个不是英文停用词)

# 场景 2: 凡人语料 (需 P4 先建索引到 /tmp/grga_fanren.db)
grga related "墨大夫" --mode graph --db-path /tmp/grga_fanren.db --json \
  | jq '[.neighbors[0:5][].term] | map(select(. as $t | ["的","了","着","是","一声","心中","看到","便是"] | index($t) | not))' \
  | jq 'length >= 3'
# 期望 true
```

**边界**:

- ❌ **不做 hub warning / seed 诊断字段** (α 推演已否)
- ❌ **不加文件扩展名过滤到 grga 主干** (场景绑定,caller 侧配)
- ❌ **不加语言级停用词表** (中英文错位,caller 侧配)
- ✅ **允许调整 PPR 数学参数** (阻尼、归一化) —— 数学恒等式加工范畴
- ✅ **允许修 adjacency 构造 bug** (稀疏化阈值、边权重归一化)
- ✅ **允许在 `related()` 内部走 raw 共现通路作为 fallback**,若 PPR
  参数调不好

**边界维度自检**(8 维清单,每条要在测试里覆盖):

- **空集**:seed 词库里不存在时,原有 not-indexed 行为保留
- **单元素**:seed 只有一个 doc 时,PPR 应能收敛而非发散
- **唯一性**:seed 跨 scope 唯一 vs 跨 scope 都存在,行为不同?
- **冲突**:同 seed 在两 scope 都是 hub,PPR 是否偏向某一 scope?
- **重叠**:多 seed 输入且交叉严重,行为是否符合预期?
- **自反**:返回结果包不包含 seed 自身?
- **可结合性**:`--cross-scope` + `--limit N` 组合正确性
- **降级路径**:PPR 不收敛时是否降级到 raw 共现?

**测试骨架建议目录**:`tests/graph/test_ppr_regression.py`,含两个场景
的 fixture(小型代码 mock + 小型中文语料 mock)。

**前置动作**:

1. 建凡人语料索引到 `/tmp/grga_fanren.db`
   (单文件 22MB,需 `--max-file-kb=25000`)
2. 记录当前 baseline: 两场景下 `grga related X --json` 输出快照,便于
   修完对比

**为什么这条排 P0**:唯一同时满足"跨场景稳健实证"+"证据充分"+"影响
面广"三条的问题。所有其他项要么场景绑定(P1),要么影响面小(P2),要么
证据不足(P3)。

### P2 · 命名修复 + search 形状字段(证据充分但影响面小)

#### P2.1 · `polysemy_hint` 语义拆分

**WHAT**:小Q 用 `graph inspect 小Q`(rare 词)时,返回的 `polysemy_hint`
字段内容是"试试 grga search 或 index rebuild" —— **内容跟字段名不
匹配**。违反 AGENTS.md 命名铁律。

**跨场景稳健性**:命名铁律是元层铁律,跨语料 100% 成立。

**改动方向**(不指定实现):

- rare / not-indexed 场景下返回的 hint,字段名应描述**"索引层原因"**,
  不叫 polysemy
- polysemy 场景保留原字段名和行为
- 两个 hint 可能出现在同一响应里,字段独立

**验收标准**:

```bash
# 索引里不存在的 seed,响应不含 polysemy_hint
grga graph inspect "不存在的词xyz9527" --db-path /tmp/grga_selfscan.db --json \
  | jq 'has("polysemy_hint")' | grep -q false
```

**边界**:

- ✅ 保留原 `polysemy_hint` 语义完整性
- ✅ 新字段命名遵守 §1.5 命名铁律(事实性:`index_hint` /
  `index_missing` / `not_indexed_hint`,不用评价性
  `low_quality_hint`)
- ❌ 不做"总 hint 字段 + 分类"这种带评价的结构

#### P2.2 · `search --json` 加形状字段

**WHAT**:小Q 反馈 `search --json` 在 `truncated: true` 时,caller 无法
判断"看到的是冰山尖还是全景"。顶层需要**描述性形状字段**。

**跨场景稳健性**:形状字段是描述性统计,跨语料稳健。这是 v2-design.md
§7.3 已定的 K 线图哲学在 search 通路的**顺延**。

**改动方向**:

- 响应顶层新增至少 `total_files_seen`(实际扫描的文件数)
- 可选新增 `total_lines_estimate`(截断前的估计总匹配行数,若能低成本
  得到)
- 不新增任何评价性字段(如 `truncation_severity: "high"`)

**验收标准**:

```bash
grga search "grga" -d /media/lqw/DATA/myrepo/grga --max-total 5 --json \
  | jq 'has("total_files_seen") and (.total_files_seen > 5)'
# 期望 true
```

**边界**:

- ❌ 不加"这次结果好不好"的评价字段
- ✅ 只加**描述性数字**
- ✅ 命名遵守 §1.5 铁律

**P2 整体成本估计**:小改动,含 tests。可与 P1 一次 commit。

## 4. 元层护栏(给明天回看的自己)

### 4.1 完备感诱惑警报

**开始使用以下词汇时立刻暂停**:

- "完整"、"覆盖所有场景"、"体系"、"一致性"
- "顺便把 X 也做了吧"
- "这样接口就统一了"
- "为了将来 Y,现在也应该 Z"

出现即暂停,重问一遍:**这一步的实证证据链是什么?场景矩阵至少两格
绿吗?**

### 4.2 双盲区自检(R44 + R52 联合)

启动任何 P 级工作前,回答四问:

1. **前提审计**:这个改动建在什么默认前提上?否定该前提还成立吗?
2. **场景稳健性**:结论在几个场景下都成立?能画出至少 2 格矩阵吗?
3. **消费者派生**:caller 能从现有输出自己算/派生这个东西吗?能就不做
4. **反面证据**:如果这条被推翻,最可能错在哪一步?现在能不能就找到
   薄弱点?

答不出来就**先降级,不立刻做**。

### 4.3 深度参与者门锁

- 任何"应该 X" 结论落地前,若已连续深挖 > 4 小时,**必须真的求外部
  视角**(不是自我扮演)
- 外部视角产出后,**必须画场景矩阵**才能接受结论
- 外部视角单场景成立时,加"在 X 场景下"限定词才落地
