## 3 · 有效用法（可复用配方，agent 视角确认过的手感）

1. **`related` 做人物/实体关系网**（身份问题入口）：单 seed、`--scope`、
   `--json`。候选里筛专名（人名/机构名），别被 `chunk_df` 高的 hub 词带偏。
   本轮 `related "楚光"` 一次就给出可用关系网——上一轮 skill 改进
   （入口路由 + `Consuming related output`）在本轮**确实生效**。
2. **`search` 限定单文件/单类型**（本轮最重要的发现）：
   `search <q> -d <父目录> -g '*书名.txt' --json`——`-g`（iglob）把搜索钉在
   目标文件上，避免跨书/跨类型污染。这是 skill 文档里**没写**的用法，靠试错得到。
3. **`--implicit-or` 用于发现，AND 用于验证**：跨段落线索用 OR 扫，确认用 AND。
4. **定位 → 展开闭环**：`search` 拿到行号 → `sed` 读章节标题确认归属 →
   `sed` 读整章。grga 的价值在"把 46 万行里的关键章节精确钉出来"，
   读原文仍需自己开 sed（见 §4-10）。

## 6 · 结论

1. **上一轮 skill 改进在本轮生效**：agent 主动用 `related` 开人物关系网、能识别
   候选为线索而非噪声——`plan-2026-09-10-related-skill-improvement.md` 的
   验收点 1/2 在本轮重放通过。
2. **本轮暴露的是"会用了之后"的摩擦**：跨书污染（#1/#3）、引号容器（#2）、
   schema（#7）、单文件用法缺失（#8）、空结果静默（#6）、AND/OR 语法不可见。
   其中 #1/#3 经作者裁定为**特性**——这是本报告最重要的认知修正：**caller 容易把
   特性误判为缺陷，而真正的缺口是"来源查询"这面镜子**（P0 修订：不改契约，用
   `graph inspect` 按需查）。
3. **改进落点分层**：skill 文字能消的摩擦落 skill（#8），契约能给的落契约（#1），
   解析/提示层 bug 落工具（#2/#6），体验层留待评估（#10）。
